## 5-3. Ⅲからの進化：探索の仕掛け（採用した方針）

Ⅲは「歩く・戦う・話す」の3動作しかなく、ダンジョンが解く場所になっていなかった。Ⅳでは `specialTiles` 機構を土台に4種の仕掛けを実装した。

| タイル | 意味 | 挙動 |
|---|---|---|
| `O` | 動かせる岩 | 進行方向の先が床なら押せる。穴なら埋まって足場になる |
| `x` | 穴 | 通れない。岩を落とすと床になる |
| `L` / `l` | 光珠灯（消／点） | 調べると点灯・消灯。マップの灯りが全点灯で `lampGates` が発動 |
| `K` | 扉 | `locks` に鍵の指定があれば鍵で、なければ別の仕掛けで開く |

**タイル書き換えの仕組み**：`MAPS[map].tiles` の文字列を直接書き換える。描画・当たり判定・監査がすべてそのまま追従するので、読み替えの通し忘れが起きない。元の姿は `MAPS_ORIG` に保持し、`G.tileEdits` に差分を記録してセーブ/ロードで復元する。

**ソフトロック対策**：`gimmickRescue()` — 穴が1つも埋まっておらず、どの岩ももう押せない状態でマップに入ると、そのマップの仕掛けを元に戻す。詰んで進めなくなるのを防ぐ。穴のあるマップには岩を2つ以上置くことを監査で強制している。

**監査に追加した項目**：岩が最初から押せるか／穴のあるマップに岩が2つ以上あるか／まっすぐ押して届く穴があるか／光珠灯を調べられる位置か／扉に開ける手段が定義されているか。BFS到達性は `x` `O` `K` を「解けば通れる」ものとして扱う。

序章のダンジョンは両方の仕掛けを必須にした（岩で穴を埋めて中段へ → 光珠灯2つで奥の扉 → ボスの間）。
